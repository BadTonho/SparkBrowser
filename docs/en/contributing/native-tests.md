# Local native integration

Validation runs locally on demand using the commands in [validation](validation.md). The repository has no GitHub Actions workflow. The Windows native suite exercises the release application through [Tauri WebDriver](https://v2.tauri.app/develop/tests/webdriver/).

## Isolated Windows run

Install Node 24, stable Rust and the normal Tauri prerequisites, then run from the repository root:

```powershell
npm ci
cargo install tauri-driver --version 2.1.0 --locked --root .cache/native-tools
./tools/testing/install-edge-driver.ps1
npm run test:native:build
$env:VELOCE_NATIVE_DRIVER = '.cache/native-tools/edge/msedgedriver.exe'
npm run test:native
```

The Edge driver installer matches the installed WebView2 runtime. Builds use `.cache/native-target` and identifier `org.veloce.browser.native-tests`. Each scenario receives a fresh directory under `.cache/native-runs/` with separate `data`, `profile`, `config`, `cache`, `logs` and `artifacts` folders. Restarts within a scenario reuse those paths. Only the test identifier accepts `VELOCE_NATIVE_TEST_RUN_DIR`, restricted to this root; production ignores it. The runner verifies both runtime identity and data directory before changing state.

Run `npm run test:native -- --list` to list scenarios or `npm run test:native -- --case notes` to run one. With no arguments the suite runs every scenario independently, continuing after failures. Stable `data-testid` selectors do not depend on UI language. Driver ports default to 4444/4445; use `VELOCE_DRIVER_PORT` for another unused pair.

Cleanup runs in `finally`, terminates only the scenario's driver process tree and removes data/profile/config/cache/logs even on failure. Reports and failure screenshots remain in each `artifacts` directory. Cleanup errors are reported without replacing the original failure. Set `$env:VELOCE_NATIVE_FAIL_CASE = 'notes'` for a deliberate post-scenario failure to verify cleanup; remove it afterward. `VELOCE_NATIVE_SCREENSHOTS=1` also retains an updates screenshot in the dialogs scenario.

The suite uses local HTTP fixtures and checks resident tab/form/scroll preservation, SPA history, shield changes, address drafts, dialogs, resize and session restoration. It also exercises named session restoration, keyword encoding, page notes, protected bulk closing, split view replacement/closure/restoration and native permission prompts. Windows test processes receive `--use-fake-device-for-media-stream`; microphone checks use a simulated device. Permission scenarios cover one-time/remembered decisions, reset, navigation cancellation, embedded origins and persistence across restart. Tests use existing commands and real DOM handlers without test-only IPC grants.

Workspace picker regression checks record native page visibility transitions: opening, closing, rapid reopening and reconciliation under a low resident limit must preserve the page behind the picker, including both split panes. Form values, scroll and document load counts must remain unchanged. Shell dialogs must still hide and restore both panes.

The direct runner also accepts a Linux `tauri-driver`/WebKitWebDriver installation through `VELOCE_TAURI_DRIVER` and `VELOCE_NATIVE_DRIVER`; that path has not been validated locally. macOS needs a separate embedded WebDriver service. Multi-monitor DPI transitions, drag gestures outside tab docking, rendering latency and aggregate process memory still require dedicated validation.

The `recovery` scenario force-stops its own test process, verifies all tabs and split focus, then checks a clean restart. `recovery-failure` injects a SQLite trigger only in the stopped, identity-verified scenario database, proves initialization failure keeps the previous snapshot, removes the trigger and retries. The `closed-tabs` and `backup` scenarios cover restoration and reviewed import with persistent preference retries.

The suite also includes `downloads` (durable checkpoints, HTTP ranges, integrity and native controls), `shutdown` (note flushing, changed-risk review, cancellation and SQLite failure), `tab-diagnostics` (real residency and revalidated protection), `zoom` (resident page scale, origins, navigation, shortcuts, restart and backup preferences), and `command-search` (bounded Unicode results, stable selection, original note URLs and reviewed session details). Download fixtures write exclusively under each scenario's `data/downloads`, never the personal Downloads folder. The complete suite has thirty independent scenarios. On Windows, `keyboard` sends real input only to the foreground isolated executable and verifies closing/reopening consecutive tabs while modifiers remain pressed; keep the test desktop available. It does not execute installers or use a VM.

## Measurements

`tab-docking` sends real pointer movement and release from both tab layouts across native pages to the page edges. It checks preview ownership, visibility and lack of foreground activation, logical/physical sizing, unchanged state during preview, both sides, replacement/swapping, ratio and tab-order preservation, Escape, injected SQLite failure and retry, page form/history/scroll-anchor preservation, workspace transfer and restart restoration. The Windows helper inspects only windows of the verified isolated executable. See [split view](../features/split-view.md).

Keep each drag crossing in one continuous W3C pointer action sequence. While the button is held, inspect native window bounds without changing WebDriver's selected WebView; switching to the preview document releases pointer capture and correctly cancels the gesture. Inspect its document only after release.

`privacy` checks the 300 px shield pop-up below its trigger, independent controls, storage-failure rollback, authenticated actions, dismissal, resize, both tab layouts, split document preservation, background auto skip, PiP source and restart persistence. The [auto skip guide](../features/auto-skip-ads.md) describes the unchanged-controller local fixtures and the explicit network-dependent YouTube check.

The three `persistence-*` scenarios inject SQLite failures into the verified isolated scenario database while the application is running. They check shield policy/history, transactional workspace deletion/activation, split replacement under a resident cap, preview isolation and ratio rollback with native pane-width measurements. Each removes its trigger and retries the operation. Together with the existing cases, the suite contains thirty independent local scenarios. See [correctness fixes](../reviews/2026-11-02/correctness-fixes.md).

`--case tab-churn` keeps ten tabs open, performs twenty create/load/close cycles, checks settled native resource counts against resident views and verifies explicit hibernation reaches one view. On Windows it samples the isolated application's descendant process tree, including working set, private committed bytes, CPU totals, handles and parsed engine roles. Full process command lines are not saved.

For a longer run, use `node tools/testing/tab-churn.mjs 10` after the same build/driver setup. It performs ten cycles per minute for the requested duration (1–60 minutes), samples each minute and writes `artifacts/tab-churn.json` in the isolated run directory. The short case is part of the full suite; the longer measurement is explicit. A growing working set requires per-process/heap investigation and is not itself proof of a leak. Run measurements sequentially with the test desktop available.

Child-WebView operations poll for the expected handle and URL for up to ten seconds instead of assuming the WebView already exists when a shell toggle updates. Additional polling is logged with elapsed time. This synchronization covers popover creation/navigation; assertions inside the child view still check its actual controls and dimensions.

After building a production release, run `node tools/testing/release-metrics.mjs` to report the Git revision, toolchain versions, frontend raw/gzip bytes and native executable bytes. These are artifact measurements, not RAM or startup benchmarks. Follow [performance validation](performance.md) for comparisons. `npm run security:check` verifies tracked/staged paths, common secret signatures, ignore rules and whitespace without printing secret contents.

Run `--case media-mute` for native audio activity, background mute and restart defaults.

`--case media-volume` measures artificial audio gain and verifies volume/navigation fallback. It also exercises the volume popover with its percentage below the slider through its own WebDriver WebView handle, checks its 200 × 64 px bounds and 6 px gap below the button, percentage alignment and updates, arrow keys, pointer dragging, dismissal, rapid reopening and both tab layouts, and verifies that neither the page nor either split pane is hidden or reloaded. Auxiliary WebView checks temporarily select the packaged document and restore the shell handle; they add no application IPC grants. The Windows resize helper changes only the verified isolated executable's client area, since WebDriver resizing can affect a single WebView instead of its parent window. JavaScript regressions cover edge clamping, drag preservation, coalescing and sending the final value when closing before the next animation frame.

`--case media-pip` validates automatic video discovery without opening volume or manually requesting a report, selects the largest eligible video through the toolbar button, and checks entry/exit in both layouts and the focused split pane. It also covers closing from another tab/workspace, external closure, cross-origin videos and protection of the source WebView. Existing internal commands retain coverage for stale documents, explicit candidates and restricted players. JavaScript regressions verify stable selection ties, shared reports, repeated-click blocking and cancellation when the focused context changes during a report. The volume popover contains no Picture-in-Picture controls.

The PiP scenario also selects the custom player's WebDriver handle and checks a moving, video-only stream, hover volume, immediate percentage updates at 0%, 100% and 200%, keyboard adjustment, Escape focus, synchronization with native volume and cross-origin frames. Synthetic videos carry generated audio tracks so amplification can be exercised without microphones or external media. Player regressions cover hover/focus/drag lifetime, stale volume acknowledgments and releasing only the mirrored tracks on closure. Custom/native session fields distinguish the application window from native fallback without changing the entry/exit commands.

After native PiP closes, the scenario activates only the verified isolated application's Windows window before checking resumed discovery. WebDriver DOM focus alone does not guarantee that the operating-system window is in the foreground; background report polling intentionally pauses while the application is unfocused.

`--case media-pip-shadow` checks the default-off appearance toggle, translated settings search, live changes without replacing the session or resizing its video area, minimized state, another workspace, volume/playback continuity and persistence after restart. External `pip-shadow-off.png` and `pip-shadow-on.png` artifacts include the Windows shadow over the isolated application's background. Capture requires foreground focus, centers the player within the isolated main client and verifies that sampled points belong only to those two verified windows before and after copying; covered regions are rejected. Screenshots stay in the run's ignored artifact directory. JavaScript tests cover invalid storage, serialized startup/changes and native failure rollback; Rust backup tests cover missing legacy fields and strict boolean validation.

Custom-player checks assert the undecorated 400 × 225 px layout, centered SVG controls and source domain, capture visible/hidden screenshots, and exercise idle hiding, keyboard focus, paused visibility, header dragging, minimize/restore and small-window bounds. The Windows floating-window helper identifies only the exact isolated executable and its floating window before inspecting/restoring it or testing native pointer dragging/resizing; pointer input requires foreground focus and a hit within that verified window. JavaScript tests use a controlled clock to verify the two-second timeout and its focus, volume and drag exceptions.

The iframe-churn regression removes an unrelated frame while another tab is focused, leaving the source's aggregate media key invalidated. Ordinary volume edits must reject that key; the floating player can adjust volume only after its source session matches fresh reports. Rust tests cover the invalidated-key guard and rejection of old source documents, generations and sessions.

`--case media-pip-continuity` switches the resource on the same video element, terminates a captured track and then blocks recapture. It verifies track replacement in the existing window, bounded recovery, an audio-free mirror, original-image restoration, final volume confirmation, the failure notice and rejection of an old session after navigation. JavaScript regressions also cover buffering, pause, seeking and callbacks from detached documents. The main PiP scenario checks the transparent 120 × 28 px volume row, absence of a background/border/shadow, its 6 px gap to the speaker's left, percentage alignment to the left of the slider, fixed percentage width, 28 px interaction area and clearance from the time label. Values of 0%, 100% and 200% must fill 0%, 50% and 100% of the slider.

`--case media-pip-fps` records finite artificial 30/60 FPS fixtures locally, then measures each for ten seconds with the source image visible, hidden and in a background tab. It requires at least 90% of the expected presentation rate and no gap above 250 ms, and writes measurements to `artifacts/pip-fps.json`. Fixture recording uses generated canvas content only. Source changes, buffering or counter resets invalidate a sample; live YouTube checks must wait for stabilization and restart samples across advertisements. A moving-frame assertion alone does not establish frame-rate quality.

After the isolated build and driver setup, `npm run test:native:youtube` explicitly runs a network-dependent YouTube check outside the 30 local scenarios. It restarts samples after source/buffering transitions, requires two stable ten-second samples with at least 90% of the delivered source FPS and gaps at most 250 ms, checks compact volume and original-image restoration, and retains `artifacts/youtube-fps.json` plus a screenshot. It reports observed source transitions; advertisements are controlled by YouTube and may not appear in a given run. The local continuity scenario deterministically covers source replacement regardless of ad availability.
