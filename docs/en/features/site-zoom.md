# Persistent page zoom

The address bar has one zoom icon, including at 100%, with a subtle highlight at other levels. It has no inline percentage or decrease/increase buttons. Clicking or keyboard-activating the icon opens a 240 px panel 6 px below it, centered on the icon and clamped 8 px from the window edges. The panel contains decrease/increase buttons, the current percentage, a slider and **Reset to 100%**. The default shortcuts remain **Ctrl + +**, **Ctrl + -** and **Ctrl + 0**, including numpad equivalents; change their bindings in Settings. Shortcuts never open the panel automatically. Levels range from 25% to 500%, with 100% as the default.

The slider uses the same standard levels as the buttons and shortcuts and applies changes while dragging. Rapid writes are coalesced and serialized, retaining the final requested value and its captured origin even when navigation changes the active site. Intermediate acknowledgements do not move the slider backward. Write failures refresh the confirmed state and show a retryable error in the panel. Previously saved nonstandard factors display their real percentage; opening the panel does not round or save them.

The transparent native panel keeps both split pages visible without reloading their documents or changing selection. It follows its button through resizing and header changes in both tab layouts, including 680 px windows. Escape, outside/trigger clicks or tabbing beyond its controls dismiss it; Escape and the trigger return focus to the icon. Tab/focused-pane/URL/workspace/layout changes, Zen, window focus loss and other panels dismiss it too. Zoom, volume and privacy popovers are mutually exclusive, and opening zoom cancels tab drags. Auxiliary actions require a current authenticated session and add no application IPC grants to content pages. Non-HTTP/HTTPS pages and the desktop-free preview show a disabled icon with an accessible explanation.

Zoom belongs to an HTTP/HTTPS origin: scheme, host and port. Workspaces share the setting. Changing it updates every resident page of that origin without recreating pages or moving focus. Hibernated tabs receive it when awakened. Split view controls follow the focused pane. Settings → Search and Navigation lists saved origins with individual reset actions. Preview shows that page zoom requires the desktop app.

Windows observers discard old WebView generations and navigation callbacks. Navigation applies the saved value rather than persisting the engine's automatic site defaults. Configured shortcuts run through the browser bridge; engine zoom hotkeys are disabled to prevent duplicate actions. See the [WebView2 controller reference](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2controller).

Backup exports use version 4 and include zoom preferences. Versions 1–3 remain importable. Zoom is applied only through the durable preference task when **Apply backup preferences** is selected. Existing local origins win on conflicts; retrying the task does not overwrite them or import data again. Transfers, partial files and run markers remain excluded.

Validation: `node tools/testing/native-smoke.mjs --case zoom`, plus the existing `backup` scenario, against the isolated native build.
