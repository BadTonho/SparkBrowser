# Custom new tab page

Opening a new tab shows a local dark page with a search field and up to five recent-site cards. The whole group sits 80 px above the vertical center, with a smaller offset in low windows and scrolling when needed. The field is at most 640 px wide with 24 px side margins. There is no logo or background image. The field receives initial focus; **Ctrl+L** still focuses the shared address bar. Enter or the search button opens the result in the same tab, using the configured Google/DuckDuckGo engine, address detection and site-search shortcuts. Empty input does nothing.

Cards come from the existing browsing history across workspaces. They show the five most recently visited distinct sites, with a 24 px favicon, domain without `www` and the last page's title. Clicking opens that site's last complete URL in the same tab, retaining its query and fragment. HTTP/HTTPS and `www` share one card; unusual ports remain separate. Known Google `.com`/`.com.br` and DuckDuckGo main/HTML/Lite search results are excluded, but normal pages on those sites remain eligible. History is scanned in batches beyond the first 200 visits when needed. Clearing history removes the cards from open new-tab pages. A history read failure leaves search available and offers **Try again**.

Search and recent-site cards open offline without remote resources or suggestions. Optional weather and Gmail widgets make backend requests only when enabled; see [new-tab widgets](new-tab-widgets.md). Windows captures favicons through WebView2 during site visits and stores validated PNGs locally: at most 512 icons, 64 KiB each and 256 × 256 pixels. Opening a new tab never contacts a favicon service or revisits a site. Older visits without a saved icon, invalid images, cache failures and platforms without native favicon capture use a packaged generic icon. Revisiting a site on Windows can supply its icon. Clearing history also clears the icon cache; callbacks from older documents cannot restore it. Fewer than five sites produce fewer cards; an empty history shows a short message. Cards wrap on narrow panes, including split view and the 680 px minimum window width. Text and keyboard labels follow the selected English/Portuguese language.

The internal logical address is `veloce://newtab`; the address field stays empty and identifies an internal browser page. Site permissions, bookmarking and page zoom are unavailable there. **+**, **Ctrl+T**, an empty startup/workspace and replacement of the last closed tab use this page. Existing saved pages and explicit destinations are preserved. Searching inside a split pane navigates that pane only.

The internal document uses the tab's normal WebView and native history. Back, forward, reload, closed-tab reopening, hibernation, saved sessions, recovery and restart support the internal address. It is not itself a browsing-history visit. Its authenticated document bridge grants no application IPC permissions to web content; stale document/request replies are discarded. Card destinations are revalidated against recent HTTP/HTTPS visits before opening in their originating pane. Refreshing cards or receiving icons preserves the search draft and keyboard focus.

An idempotent migration creates the rebuildable `site_icons` cache; recent sites continue using the existing history. Backup exports remain version 4, exclude the icon cache and continue importing versions 1–4. Only tabs and session pages accept the exact internal address; external-data URL restrictions remain in place. Older application builds that only accept HTTP/HTTPS tabs may reject backups containing the new internal page.

Validation: `npm run validate` and the isolated native `new-tab` scenario, with regressions for keyboard, split groups, workspace switching, closed tabs, workspace persistence, backup and recovery. See [native tests](../contributing/native-tests.md).
