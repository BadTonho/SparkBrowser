# Tab media controls

On Windows, tabs that emit audio show a speaker button in both layouts. Click it to mute the entire tab, including embedded frames and Web Audio, without selecting it. Muted tabs keep the button visible. The setting follows the tab through navigation and hibernation during the current run; new, reopened and startup-restored tabs begin unmuted. Preview and unsupported engines do not show a functional mute control.

## Page volume

The volume button beside the address opens a compact 200 × 64 px popover directly beneath the button for the focused tab, including split view. It contains a horizontal slider, from 0–200% in 1% steps, with the percentage centered below it in 12 px text. The percentage updates immediately while dragging or using the arrow keys and follows the applied level when the player responds. The page stays visible without dimming or blur. Set the slider to 100% to restore the original level. Mute preserves the chosen level. New, reopened and startup-restored tabs begin at 100%; navigation, hibernation and workspace changes retain adjustments during the run.

The slider receives keyboard focus; arrow keys adjust the level. Escape returns focus to the button. Clicking the button again or outside the popover closes it and commits the latest adjustment. Tab closes it and returns focus to the button so normal keyboard navigation can continue. Changing the focused tab, document or workspace, or opening another browser overlay, also closes it. Resizing keeps it anchored within the window. Unsupported sources and preview show a disabled slider with its percentage below. The slider exposes its label and percentage to assistive technology; the visual percentage does not add a duplicate announcement.

100% preserves the player’s own level. Compatible HTML media can be amplified locally with Web Audio and an element capture stream, without recording or transmitting content. Unsupported players retain their original audio and limit amplification to 100%; sources without volume support keep native mute available through the tab speaker button. Autoplay restrictions can require interaction with the page. Outside an active drag, the slider follows the applied level.

The Rust backend tracks default execution contexts, including embedded frames, and binds fixed operations to the WebView generation and document. Slider updates coalesce and stale documents cannot receive a previous page’s adjustment. A transparent child WebView renders the popover above both native panes without hiding them or creating another operating-system window. Only its authenticated volume/dismiss actions reach the shell; application IPC remains restricted to the main shell. No media preference is written to SQLite or backups.

Run `--case media-volume` in the isolated Windows native suite for attenuation, measured amplified waveform, player-volume independence, coalescing, stale navigation, cross-origin fallback and restart defaults.

Players with native HTML controls retain 0–100% adjustment; amplification is unavailable to preserve their own mute controls. Direct player-level changes retain the tab multiplier.

## Floating video

The floating player's volume control is a transparent 120 × 28 px row, centered vertically 6 px to the left of its speaker, without a background, border, shadow or rounded box. The 12 px percentage sits to the left of a 2 px slider with an 8 px thumb. A fixed percentage width prevents movement between 0%, 100% and 200%; the slider retains a 28 px interaction area and a visible keyboard focus indicator. The time label leaves room for the control, including at the minimum window size; the browser's separate address-bar volume popover is unchanged.

After the first mirrored frame, the source video's image is hidden with a temporary class while its layout, playback and audio remain intact. Closing or failing the floating session removes that class and restores the image without pausing the original. The capture session follows video-track additions, removals and endings on the same source element, including advertisement/content transitions. New audio tracks never enter the mirror. A stalled mirror can recapture that same element with at most two attempts until frames remain healthy for two seconds; pauses, seeking and buffering do not consume attempts. Permanent failure restores the source, commits the last volume edit, closes the custom session and uses the existing media notice. The failure notification uses the authenticated session channel; it adds no public command or general IPC access.

The custom player starts at approximately 400 × 225 px without a Windows title bar, with a thin border and uncropped video. Overlaid SVG controls show the source document's domain and minimize/return/close buttons at the top, play/pause and ten-second skips in the center, and a fine progress line, time and volume at the bottom. No favicon request is made. Drag the free header area to move the window; its edges remain resizable. The native PiP fallback keeps the engine's appearance.

Controls appear on pointer movement, keyboard focus or interaction and fade after two seconds of inactivity while playing. Pausing, focusing a control, dragging or opening volume keeps them visible. Hidden controls do not intercept pointer clicks; keyboard focus reveals them again. The volume control retains its separate 300 ms dismissal timer and 0–200% slider with the percentage to its left. UI timers belong to the floating window, so hiding the source tab does not delay its controls. Minimizing preserves playback; restoring reveals the controls. Only authenticated, session-bound minimize/drag actions are added to the auxiliary channel, without general application IPC permissions or subtitle controls.

Click the **Open floating video** button immediately to the right of volume and before zoom in the address bar. It is available in both tab layouts and opens Picture-in-Picture directly for the focused tab or split pane. If several videos are compatible, it chooses the largest intrinsic `width × height` reported by the player; equal areas retain report order. Compatible sources use a resizable, always-on-top window with application controls. Only a local video track is mirrored: audio, playback position and the original element remain in the source tab. Protected/disabled players and policy-restricted frames are not bypassed.

Hover over the floating window's speaker to reveal the volume slider and percentage. Keyboard focus or clicking the speaker also opens it. The slider controls the source tab's existing 0–200% level in 1% steps, even from another tab or workspace. Its percentage updates immediately and reconciles with the applied volume; the browser's volume popover and floating window share the same value and amplification limits. Unsupported volume adjustment disables the slider. The panel stays open while hovered, focused or dragged and hides 300 ms after leaving that area. Escape hides it and returns focus to the speaker.

Play/pause, ten-second backward/forward buttons and seeking control the original video. Return to tab selects its workspace and focuses the browser. Closing the floating window commits the last volume edit and leaves the original playback running. The mirrored video is permanently silent and contains no audio tracks, avoiding duplicate sound. Its tracks, timers and listeners are released on closure or document destruction. No media is recorded or transmitted. If local video capture is blocked, the existing native PiP opens instead and the media notice explains that custom controls are unavailable.

While a floating video exists, the same button stays highlighted and its action becomes **Exit floating mode**, even from another tab or workspace. Only one floating video is active at a time. Without a compatible video, the button remains visible but disabled, with an explanatory tooltip. Preview and unsupported engines also show it disabled. Labels and active/busy states are accessible to assistive technology. The volume popover retains only its slider and percentage.

One shared report loop discovers videos without opening the volume popover. It refreshes the focused resident tab on tab/navigation changes and once per second while the application is focused and visible; automatic failures are silent and background tabs are not polled. Concurrent reports for the same tab share their pending request. A click waits for a fresh report and cancels entry if the focused tab, workspace, URL or document changes. Repeated clicks are blocked during the operation, and action failures use the existing media notice.

Selecting the originating tab also selects its workspace. The toolbar exit action closes only the floating window. Switching tabs/workspaces and opening browser overlays retain it. Closing its tab or navigating to a new document ends it. A paused floating video still protects its source WebView from hibernation and organizer bulk closure; diagnostics explain that protection. Normal close/update review also includes a floating video.

Native state notifications are bound to the current execution context and document, including accessible cross-origin frames. The media bridge reports playback/PiP state only and grants no browser commands to external pages. Unsupported engines and preview cannot use the native media services.

The custom window has no application IPC permissions. A short-lived, single-use opening request and a sequenced media-only channel bind it to the source WebView generation, frame, document and video session. Volume edits reuse the shell's coalesced writer and stale-document checks. Unrelated iframe additions/removals can update the aggregate volume key only while that original source session still matches. Replies acknowledge their originating edit, so an older applied value cannot replace a newer drag. Reports distinguish custom and native PiP; both retain the same source protection and global exit behavior.

Run `--case media-pip` for automatic discovery, largest-video selection, toolbar entry/exit in both layouts and split view, background ownership, overlays, paused protection, external closure, navigation, stale candidates, cross-origin frames and closing the source tab. All scenarios use generated media and isolated profiles.
